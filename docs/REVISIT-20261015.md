# Graphene flake revisit — October 15, 2026

The Review interface can open a saved observation in `/revisit`. Opening the page,
reading metadata, and polling status do not connect the microscope. This feature
has been exercised with fake microscope clients and real saved-source metadata;
no live revisit has been performed. The previous chips have been removed, so the
current placement cannot be treated as unchanged.

## Operator workflow

1. Select a particular flake observation and open **Revisit**. Check the source
   run, chip, saved image and required objective. A grouped flake still resolves
   to one exact observation; source coordinates are never averaged across views.
2. Load the specimen, engage the displayed objective manually, and set a focus
   height safe for the intended XY travel. Confirm specimen identity and clearance.
   The software does not change objectives, lamp settings, focus height or ZEN jobs.
3. Choose **unchanged** only if chip placement, orientation and the stage coordinate
   frame are unchanged since acquisition (including no homing/coordinate reset).
   Connect explicitly, then choose **Move to flake**. Identity placement is an
   operator assertion, not an image-based registration.
4. For a reloaded specimen, select a visible landmark in a saved source image.
   Source clicks use native image pixels, the calibrated two-dimensional camera
   transform and its half-pixel centre convention. Release the hardware session
   before manual ZEN/joystick positioning; locate that same feature at the camera
   centre, reconnect explicitly, and record its live stage readback. Repeat with
   a well-separated second feature on the same chip, then apply registration.
   Release closes the adapter and lease; it does not switch ZEN modes or reopen
   old jobs. Reconnect verifies ownership, profile, source pins and controller
   bounds again. Manual focus changes during the released interval are allowed.
5. Two anchors fit rotation and translation, with unit scale. A single anchor is
   accepted only with explicit confirmation that orientation is unchanged. This
   determines translation only. Incorrect source/current distance correspondence
   or a baseline too short relative to localization allowance is refused.
6. Move to the flake, inspect the live field and adjust focus manually as needed.
   The arrival receipt verifies XY and preserved current Z. It does not establish
   flake identity or focus quality. **Stop** terminates the session; it cannot be
   re-armed. **Disconnect** closes it. Begin a fresh session after a stop or crash.

The four displayed inferred corners come from intersections of **unexpanded**
measured edge lines, not the raster envelope. In the saved chip001 example their
allowance is 235.009 µm, expressly not a confidence interval. Some actual corners
are jagged or further displaced from the fitted intersection. These are coarse
registration aids; a matching visible source-image corner/feature is better.
Image-point registration records a 5 µm operator localization allowance per
anchor. It is an assumption, not independently measured accuracy. Reported target
allowance includes that assumption, baseline mismatch and angular propagation.
One-point orientation confirmation cannot bound an unreported rotation error.

## Backend and HTTP integration

Production source is `research/software-next-20261009/flakefinder/`:

- `revisit_geometry.py`: pinned source resolution, inferred-corner construction,
  native-pixel conversion, registration and target propagation.
- `revisit_control.py`: read-only server facade, immutable session requests,
  command queue and dedicated hardware worker. Importing it is offline.
- `zen.py`: opt-in `motion_only=True`; normal capture behavior remains default.
  Motion-only connection uses ordinary managed receipt storage checks instead of
  the raw-capture reserve, and `capture()` refuses before accessing hardware.
- `scan_service.py`: scan Start refuses an active or manually released revisit
  under the shared launch lock. A released session must close before a scan starts.

`RevisitControl(project)` methods:

| Method | Parameters / effect |
| --- | --- |
| `metadata` | `run_id, observation`; saved target, corner aids, 999 compact source-image fields in the current example, required objective and source hashes |
| `status` | optional `session_id`; persisted state only; absent workers are never restarted |
| `begin` | `run_id, observation, placement_mode, operator_confirmed=True, limits=None, duration_s=1800`; explicit fresh subprocess launch |
| `anchor` | `session_id` plus exactly one of `corner_id`, `source_observation`, or `source_field` + `source_pixel_xy` |
| `register` | `session_id, orientation_unchanged=False`; two anchors or explicitly asserted one-anchor translation |
| `move` | `session_id, observation=None`; same run and chip; preserves fresh current Z |
| `release` / `reconnect` | release adapter/lease for manual positioning; reconnect requires `operator_confirmed=True` |
| `stop` / `close` | session-specific terminal control record; independent monitor interrupts in-flight motion |

Mutation responses contain `session_id`, `state` and, for queued commands,
`command_id`. Poll until `last_command.command_id` matches or the session reaches
a terminal state. States include `queued`, `connecting`, `registration_required`,
`ready`, `moving`, `released`, `stopping`, `closed`, `stopped`, `failed` and the
read-time `interrupted` status for an absent process.

Default limits are the fresh controller's XY/Z ranges, read after acquiring the
host-wide lease. Optional `Limits` fields may narrow them; maximum XY segments
remain at most 1200 µm. The adapter performs bounded segmented travel and settled
readback verification. Physical controller ranges are not a collision model;
the operator must ensure current-Z travel clearance. No historical Z or old
focus plane is used, including after reconnect.

## Provenance and failure behavior

Each new `data/revisit-...` folder contains an immutable `scan-request.json`,
PID/nonce-bound `acquisition-authorization.json`, exclusive `worker-start.json`,
status, command receipts and successful move receipts. Existing acquisition
STOP/hold files remain unchanged. Changed hold bytes revoke the scoped session.
The viewer's process environment never receives the worker authorization.

The exact selected request, chip manifest, coverage plan, analysis selection,
model, analysis plan, field JSON and source frame position metadata are pinned.
The saved revisit point is independently recomputed from the native source pixel
and compared to its saved XY. Only metadata is read for movement; no raw TIFF is
rewritten or interpreted as a new capture. Selected preview bytes are pinned as
display derivatives, not promoted to scientific raw evidence. A source image
anchor additionally pins its position sidecar and displayed preview. Source or
installed-profile changes refuse subsequent motion.

Only the dedicated worker connects; it acquires the global microscope lease
before live stage/optics readbacks. Active scans, unconfirmed prior closure,
unregistered reloaded placements, source/profile mismatches, expired sessions
and out-of-bounds destinations fail before motion. The independent monitor
checks STOP, close, authorization and the session deadline; connection attempts
have a 120-second monitoring deadline in addition to adapter RPC timeouts. There
is no automatic hardware reconnect after process exit.
