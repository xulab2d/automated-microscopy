# Quantitative brightfield imaging profile

The current stand configuration identifies the reflected-light source as **RL LED Lamp**, class `MTBCtrlLampRLAxioscopeLab`, despite its legacy API identifier `MTBRLHalogenLamp`. It is not evidence of a halogen lamp. Its documented configured conversion is AD 1–1024 to 0–100%; a readback of −0.097847% corresponds to AD 0, outside that valid range. Treat that readback as an unilluminated or invalid state, not a usable illumination profile.

`FlakeFinder Quantitative Camera.czjob` is a separate camera-only job. Its typed runtime resources are `ff_exposure_ms` (double) and `ff_white_balance` (string, three comma-separated values). Auto exposure, auto white balance and HDR are disabled. The initial white-balance value is the installed ZEISS Axiocam 305 color **5500 K preset**, `0.45050752,1,0.571064`, read from `C:\Program Files\Carl Zeiss\ZEN core\AxioCamWhiteBalance.xml`. The same table contains a 3200 K preset, `0.66098,1,0.40667`.

The 5500 K preset is a reproducible starting setting for the LED, **not a measurement of this lamp's spectrum or a white-reference calibration**. The vector's channel order and interpretation are passed unchanged from the vendor table; do not reinterpret its entries as ordinary multiplicative gains. The existing acquisition used `0.027312621062124,0.10921695976961,0.14266182058968`. After importing the new job, capture the same stationary field with each setting, optimize exposure and inspect each channel's clipping and substrate variance. Record the chosen string in the profile and all image metadata. Loading a resource successfully does not itself prove that the camera applied it; compare image measurements.

Do not run white balance on purple 285 nm SiO₂ as though it were a white specimen. Its wavelength-dependent reflectance is the measurement reference. A neutral reflector under the same illumination can provide an actual white-reference calibration; until then, use one fixed vendor profile and substrate-normalized contrast. Keep lamp level, white balance, camera mode and exposure fixed during each acquisition dataset. Changing white balance requires a new optical profile and a separately calibrated color model.

Existing stationary captures in `data/optical-control-test` support that fixed-light decision. On every eighth pixel with reference intensities 500–3500 and comparison intensities 100–3500, halving exposure from 200 to 100 ms gave median RGB ratios 0.496, 0.506, 0.505. Lowering the LED setting from 93.44% to 80.04% at 200 ms gave ratios 0.814, 0.663, 0.729. Thus the exposure response is approximately linear in this test, but the illumination change altered channel ratios. The test does not establish whether LED spectral changes, camera processing or another optical effect caused that change. It does justify keeping illumination fixed for color measurements. The 100 ms pair's red-channel affine-fit residual MAD was about 50 ADU versus 14–15 ADU in green/blue; compare this noise after the new vendor preset rather than assuming the old white balance is suitable.

The Axiocam 305 digitizes at 12 bits. The streamed RGB image is stored in a 16-bit container, so the current measured white level is 4095, not 65535. The saved TIFF preserves the streamed RGB values, but these are camera color output, not an unprocessed Bayer measurement. Keep JPEG tone mapping out of analysis. Verify exposure linearity on unsaturated pixels and use the brightest RGB channel when selecting exposure. A reasonable initial acquisition target is 70–75% of full scale in the substrate's high percentile; inspect saturation in bright objects separately. A long exposure that clips one channel destroys quantitative contrast even when the grayscale histogram looks acceptable.

At the new 20×/0.40 objective, the nominal sampling is about 0.1725 µm/pixel based on the previous 10× sampling. Measure the camera-to-stage transform again at 20×; an old 0.345 µm/pixel stream metadata value is not validation. Save an objective-specific focus result, measured transform and optical profile. The encoded turret must return a stable configured position: the MTB API explicitly defines position 0 as outside a click stop. It must not be interpreted as zero-based 10× or assumed to mean 20×.

For uneven illumination, a same-objective dark/flat reference is preferable to a fitted sample background. If no uniform reference is available, background fitting must exclude edges, tape, flakes and saturation, and report its residuals. A flat derived from a contaminated tile can erase real material or create false contrast. RGB gains do not create information; within a linear, unsaturated system they cancel in per-channel sample/substrate ratios. Image quality therefore needs actual contrast-to-noise and edge measurements rather than a visually attractive white background.
